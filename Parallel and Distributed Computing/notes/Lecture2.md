# Cloud Computing
**Definition:** Cloud computing is the practice of storing, managing, and processing data on remote servers over the internet instead of using local computers.Instead of running programs on your PC or machine, they run on remote servers called cloud server.

- Cloud computing allows user to access applications and dara from anywhere through the internet.
Real-life Examples:
- Google Drive
- Dropbox
- Netflix
- Gmail
# Why Cloud Computing is Used:
1.Pay as You Go:
User pay only for the resources they use.  
Example:  
A startup pays only for the cloud storage it currently needs.  
2.24/7 Availability:
Cloud services are available anytime.  
Example:  
Students can access Google Drive from home, university, or mobile phone.  
3.Device and Location Independent:  
You can access data from any device connected to the internet.  
Example:  
You upload a document from your laptop and later open it on your Phone.  
4.Easy Deployment:  
Companies can quickly deploy applications without buying expensive hardware.  
Example:  
A company can launch a website in minutes using cloud hosting.  
5.Scalability:  
Cloud system can increase or decrease resources depending on demand.  
Example:  
During big online sales like Black Friday, e-commerce websites need more computing power.  
Cloud servers automatically scale up.  
# On-Premise Vs Cloud Computing
1.Payment: "Higher pay, less scalability" vs "pay for what ypu use"
On-Premise(old way):You Pay a huge amount of money upfront before you even start using it.  
Example:  

- Company needs servers for 100 employees.
- On-Premise Cost: buy 10 servers=$50,000
- Pay $50,000 today, even if you  only use 10% of their capacity
- If company grows to 200 employees, need to buy 10 more servers = another $50,000
- If company shrinks to 50 employees, stuck with extra servers you paid for.  
Cloud Computing (New Way):You pay only for what you actually use, like your electricity bill.  
Real Example:
- Company needs servers for 100 employees
- Cloud Cost: Rent servers = $500 per month
- Pay $500 this month for exactly what you need
- If company grows to 200 employees → scale up, pay $1000
- If company shrinks to 50 employees → scale down, pay $250

2.Server Space: "Allot huge space for servers" vs "No server space required"  
On-Premise:You need a physical room or building just to keep your computers.  
Real Example:  
- Company needs a "server room"
- Requirements: Air conditioning (servers get hot), raised floors (for cables), fire suppression system, backup power
- In a city like Mumbai, office space costs ₹200 per square foot
- A 500 sq ft server room costs ₹1,00,000 per month just for space!
- Plus electricity for cooling: another ₹50,000 per month  
Cloud Computing:The cloud provider has the server rooms. You just use them over internet.
Real Example:
- Company pays $0 for server room space
- All servers are in Amazon or Google's data centers
- These data centers are in places with cheap land and electricity
- You access everything from your normal office (no special room needed)

3.Maintenance: "Appoint a team for hardware and software maintenance" vs "No experts required"
On-Premise:You need to hire IT people to take care of your computers.  
Real Example:
Company needs:  
2 hardware engineers (to fix broken servers) = ₹1,20,000/month  
2 system administrators (to install updates) = ₹1,00,000/month  
1 network engineer (to manage connections) = ₹80,000/month  
1 security expert (to prevent hacking) = ₹1,00,000/month  
Total monthly salary cost = ₹4,00,000
Plus when someone quits, hiring and training costs  
Cloud Computing:The cloud provider's experts handle everything. You focus on your business.  
Real Example:  

- Company pays $0 for hardware maintenance
- If a server breaks in Amazon's data center, Amazon fixes it (you don't even know)
- Security updates are applied automatically
- You need only your business IT team, not hardware specialists

4. Data Security: "Poor data security" vs "Better data security"  
On-Premise:Your data security depends on YOUR efforts and budget.  
Real Example - Security Problems:

- Physical theft: Someone walks into server room, steals hard drive
- Natural disasters: Fire/flood destroys servers
- Insider threat: Employee steals customer data
- Limited budget: Small company can't afford enterprise security
- Outdated security: Forgot to update firewall, hackers get in
- Real Incident: A small clinic stored patient records on a server in their office. Someone broke in at night and stole all hard drives. Patient data lost forever.

Cloud Computing:World's best security experts protect your data.  
Real Example - Cloud Security:

- 24/7 physical security: Guards, cameras, biometric access
- Encryption: Data is scrambled so even if stolen, can't read
- Redundancy: Data copied to multiple locations
- Expert team: Google/Amazon hire the best security experts
- Regular updates: Security patches applied automatically
- Real Fact: Amazon Web Services spends millions on security - more than most countries! Your data in cloud is safer than in most company server rooms.

5.Data Recovery: "Less chance of data recovery" vs "Disaster recovery"
On-Premise:If your servers are destroyed, your data is probably gone forever.  

Real Example - Disaster Scenarios:

- Fire: Server room catches fire → all data destroyed
- Flood: Water damages servers → hard drives dead
- Ransomware: Hackers lock your files → can't access
- Hard drive crash: Disk stops working → data lost
- Real Incident: A company in Chennai had their server room flooded during rains. All customer data lost. Business closed within 6 months.

Cloud Computing:Your data is automatically backed up in multiple places.  
Real Example - Cloud Recovery:

- Multiple copies: Your data stored in 3 different cities
- Automatic backup: Every change saved instantly
- Quick recovery: If one data center fails, switch to another in minutes
- Disaster proof: Even if Mumbai data center floods, Pune copy still works  

Real Example: Netflix stores movies on AWS. If one data center has problems, viewers automatically get movies from another center. Users don't even notice!

# Types of Cloud Deployment Models:
Deployment models define how cloud infrastucture is used.  
1.Public Cloud:Public clouds are owned by Third-party providers and available to the public.  
Example:Amazon Web Services(AWS)  
Companies rent computing resources from cloud providers.  
2.Private Cloud:Private cloud is used by one organization only.  
Example:A bank may run its own private cloud for financial data.  
3.Hybrid Cloud:Hybrid cloud combines public cloud and private cloud.Some data is stored privately, while other services run on public cloud.  
Example:A hospital keeps patient records in a private cloud nut uses public cloud for website hosting.  
# Cloud Service Models
1.Intrastructure as a Service(IaaS):It provides basic computing infrastructure such as servers, strorage, and networks.Users manage operating systems and applications themselves.  
Example:Amazon EC2 allows companies to rent virtual servers.  
2.Platform as a Service(PaaS):It provides a platform where developers can build and deploy applications without managing hardware.  
Example:Google App Engine allows developers to run applications without managing servers.  
3.Software as a Service(SaaS):It provides complete software applications through the internet.Users do not manage infrastructure or platforms.  
Example:
- Gmail
- Google Docs
- Mirosoft Office 365  

# Differences Between IaaS, PaaS and SaaS
## Difference Between IaaS, PaaS, and SaaS

| Feature | IaaS (Infrastructure as a Service) | PaaS (Platform as a Service) | SaaS (Software as a Service) |
|--------|------------------------------------|------------------------------|------------------------------|
| Definition | Provides virtualized computing resources such as servers, storage, and networking over the internet. | Provides a platform for developers to build, test, and deploy applications without managing infrastructure. | Provides ready-to-use software applications through the internet. |
| User Control | High control over OS, applications, and data. | Control only over applications and data. | Very little control, users simply use the software. |
| Managed By Provider | Hardware, networking, and virtualization. | Hardware, networking, OS, runtime environment. | Everything including application, data storage, and infrastructure. |
| Managed By User | Operating system, applications, middleware, and data. | Application code and data. | Only software usage and settings. |
| Main Purpose | Provides computing infrastructure. | Provides development environment. | Provides complete software solutions. |
| Target Users | System administrators and IT teams. | Application developers. | End users and organizations. |
| Flexibility | Most flexible because users manage many components. | Moderate flexibility. | Least flexible but easiest to use. |
| Cost | Pay for infrastructure resources used. | Pay for platform usage and development environment. | Usually subscription-based pricing. |
| Examples | Amazon EC2, Google Compute Engine, Microsoft Azure VM | Google App Engine, Heroku, AWS Elastic Beanstalk | Gmail, Google Docs, Dropbox, Microsoft 365 |
| Real-Life Example | A company renting virtual servers to host its website. | A developer deploying a web application without managing servers. | A student using Google Docs to write assignments online. |  

# Common Characteristics of Cloud System:
characteristics explain how cloud platforms manage resources and deliver services to millions of users.  

1. Massive Scale: Massive scale means that cloud systems operate with very large amounts of computing resources, including thousands or even millions of servers.
Cloud providers build huge data centers containing large numbers of machines that work together to provide computing power, storage, and services.  
Example  
Companies like Amazon Web Services, Google Cloud, and Microsoft Azure run massive data centers with millions of servers to serve users around the world.  

- For example, when millions of people watch videos on Netflix at the same time, the cloud infrastructure handles all the traffic without crashing.

2.Geographic Distribution:Cloud infrastructure is distributed across multiple locations and countries around the world.  
This means cloud providers place their data centers in different regions so users can access services quickly and reliably.  
Why it is important
- Reduces delay (latency)
- Improves reliability
- Provides backup in case one data center fails  
Example  
If you use Google Drive, your files might be stored in multiple data centers across different countries. Even if one server fails, your data remains available from another location.  

3.Virtualization:Virtualization is a technology that allows one physical computer to run multiple virtual machines (VMs).  
Instead of dedicating one server to one application, virtualization divides the server into several virtual environments.  
Each virtual machine behaves like a separate computer with its own operating system.  
Why it is important  

- Efficient use of hardware
- Lower cost
- Better resource management
Example  
A single physical server in a cloud data center might run:  
- one VM for a website
- one VM for a database
- one VM for file storage
- All running on the same physical machine.

4.Low Cost Software:Cloud systems reduce the cost of software and hardware for users.  
Instead of purchasing expensive software licenses or servers, users can rent services from cloud providers.  
This reduces initial investment and allows businesses to focus on their core work.  
Example  
Instead of buying expensive office software, companies can use Microsoft 365 or Google Docs through the cloud and pay only for subscriptions.

5.Service-Oriented Architecture (SOA):Cloud computing follows a service-based architecture, meaning different functionalities are offered as services.  
Users can access specific services depending on their needs.  
These services are typically provided through the internet using APIs or web interfaces.  
Example  
Cloud providers offer services such as:  

- storage service
- computing service
- database service  
For example, Amazon Web Services provides services like:  
- EC2 for computing
- S3 for storage
- RDS for databases

Cloud computing offers many benefits.

# Disadvantages of Cloud Computing
Cloud computing also has some limitations.

- Internet Dependency:Cloud services require a stable internet connection.
- Security Concerns:Sensitive data stored online may be vulnerable.
- Limited Control:Users have less control over infrastructure.
- Compatibility Issues:Different cloud providers may use different APIs and systems.  
Example:  
Moving applications from one cloud platform to another may require changes.
